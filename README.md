# ヨミクラーベ — セットアップ手順

文書（PDF / Word）を「テーブル」に並べて読み比べるアプリです。
GitHub Pages ＋ Firebase Realtime Database で動きます（Firebase は無料の Spark プランでOK）。

> Firebase を設定しないまま開くと **デモモード** で動きます（その端末のそのブラウザ内だけ。別タブで開くと複数人の動きを試せます）。

---

## 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ で「プロジェクトを追加」（例：`yomikurabe`）
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーション：**シンガポール（asia-southeast1）**
   - 「ロックモードで開始」でOK（次の手順でルールを入れます）
3. 「ルール」タブを開き、同梱の `database.rules.json` の中身を丸ごと貼り付けて「公開」
4. プロジェクトの設定（歯車）→「マイアプリ」→ ウェブアプリ（`</>`）を追加
   - 表示される `firebaseConfig` の値をメモ

※ Firebase Storage は使いません（2024年以降、Storage は有料プランが必要になったため、PDFはデータベースに分割保存しています）。

## 2. index.html に設定を貼る

`index.html` の上の方にある `FIREBASE_CONFIG` に、メモした値を貼ります。
**`databaseURL` を必ず入れてください**（例：`https://yomikurabe-default-rtdb.asia-southeast1.firebasedatabase.app`）。

## 3. GitHub Pages で公開

1. GitHub に新しいリポジトリ（例：`yomikurabe`）を作り、`index.html` をアップ
2. Settings → Pages → Branch を `main` / `(root)` にして Save
3. `https://kwmrdoe14-tech.github.io/yomikurabe/` で開けます

## 4. 使い方

### 先生
1. 参加画面の下「先生メニュー」→ 最初の1回だけ **先生用の合言葉** を決める
2. テーブル名を入れて「作成」→ 5文字のコードができる
3. 「共有」でコード・QRコード・リンクを表示（プロジェクターに映すと便利）
4. テーブル内では、誰の文書でも削除・名前変更でき、「アップ受付」を停止できます

### 参加者（ログイン不要）
1. コードと名前を入れて「参加する」（QR/リンクから来た場合はコード入力済み）
2. 「アップロード」で PDF / Word(.docx) を追加。**名前を出す / 匿名** を選ぶ
   - 匿名を選ぶと名前はデータベースに保存されません（先生にも分かりません）
3. 文書をタップすると読めます。ペン・マーカー・消しゴム・メモが使えます
4. 「選択」→ 2〜3件選んで「並べて読む」、またはビューア上部の「並べる」で横並び比較
   - 「スクロール連動」をONにすると並べた文書が一緒にスクロールします

### 個人だけのもの（他の人と同期しません）
- 線・マーカー・メモ
- お気に入り（★）
- グループ分け（色つき。「グループ別」で区切って表示、チップで絞り込み）
- NEW 表示（まだ開いていない文書）

これらは **その端末のブラウザ内** に保存されます。別の端末やブラウザでは引き継がれず、ブラウザのデータを消すと消えます。

## 5. 制限・注意

- 1ファイル 15MB まで。古い `.doc` は非対応（Word で .docx か PDF に保存し直す）
- Word → PDF 変換は端末内での簡易変換です。文字・表・画像は残りますが、**縦書き・段組み・図の細かい配置は崩れます**。崩れる場合は Word の「PDFとして保存」でPDFにしてからアップしてください（変換後のPDFは画像なので、文字検索・選択はできません）
- Firebase 無料枠：保存 1GB、ダウンロード 10GB/月。一度開いた文書は端末にキャッシュされるので、再度開いても通信量は増えません。不要になったテーブルは先生メニューから削除してください
- 合言葉を変えたいとき：Firebase コンソールの Realtime Database で `config` を削除 → アプリの先生メニューで再設定
- ログインなしの仕組みなので、データベースURLを知っている人は技術的にはデータを読み書きできます。成績など機密性の高い文書には使わないでください
